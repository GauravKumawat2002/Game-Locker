# Windows QA and remediation

The audit covers GameLocker's Windows service, configuration app, NTFS lock and unlock, vault, recovery utility, and installer. Filesystem checks used disposable directories and synthetic file contents on Windows. The baseline solution built with one warning and passed 65 Basic tests.

| ID | Severity | Baseline finding and evidence | Regression condition |
| --- | --- | --- | --- |
| QA-01 | Critical | The `LockFolderAsync` journal was written with `AclApplied=false` before the live ACL changed. A fixture left in that intermediate state reported `Unlocked`. Unlock deleted the journal while the fixture still had the lock ACL. | A pending snapshot remains recoverable. Restore verifies the original ACL before clearing the record. |
| QA-02 | High | On a fixture with an outstanding journal and restored live permissions, relock returned `Locked` and left the live ACL open. The baseline verifier accepted ACLs with direct allow entries for accounts outside SYSTEM and Administrators. | Relock reapplies the expected protected ACL and retains the original snapshot. |
| QA-03 | Critical | Vault encryption deleted originals before saving the batch manifest. A fixture with a pre-existing `.enc` file lost that file and produced an empty manifest. Decryption opened an existing plaintext destination with `FileMode.Create` and removed it on failure. | Every new ciphertext is staged, hashed, and journaled before GameLocker releases the original. Restore checks the hash and preserves conflicting copies. |
| QA-04 | Critical | An unmanaged fixture containing `asset.enc` reported `Unknown`, which sent scheduled unlock through legacy decryption. The same path could remove unrelated explicit denies or reset an unrelated protected ACL. | The scheduler leaves unmanaged `.enc` files and ACLs alone. Recovery handles a specifically selected legacy file and retains its ciphertext. |
| QA-05 | High | The top-level test check rejects a reparse point only at the selected leaf. Recursive file enumerations follow child reparse points. The vault recovery path combines manifest entries with the folder without checking path containment. | A selected path with a reparse ancestor is rejected and scans and vault work stay within ordinary paths under the selected folder. |
| QA-06 | Critical | The ConfigUI test lock keeps its only ACL snapshot in a local variable. Closing the process before `finally` loses it. Removing a folder separately invokes the legacy ACL helper and scans every `.enc` file, then lets the saved service configuration relock it. Clearing can also leave outstanding folders behind. | Test lock uses the shared recoverable journal. Removing or clearing monitored folders hands restoration to the same reconciliation path and keeps unresolved records available. |
| QA-07 | High | `FolderStateStore.Save` ignores a failure to secure the state store. Unreadable or malformed records are returned as absent, so subsequent operations can replace the only recovery snapshot. Concurrent callers use the same uncoordinated temporary path. | Mutation stops on an unsecured or unreadable store, and one operation owns each folder journal at a time. |
| QA-08 | High | The service and Recovery initialize vault keys up front, so damaged or missing key files can stop ACL-only operations. Neither the primary installer build nor its payload contains `GameLocker.Recovery`. | An ACL-only operation is independent of vault keys and the standard installer includes an accessible recovery tool. |
| QA-09 | High | A fixture with `config.dat` and missing sidecars returned `NotFound`. ConfigUI used the overload that returned the same value for first run and load failure. Saving could replace the encrypted config. | The app reports unreadable settings and preserves the existing configuration until it can be recovered. Clearing saves an empty schedule and keeps the recovery keys and backup. |
| QA-10 | High | The lock checked the selected folder's ACL only. Descendants with protected permissions or explicit grants retained their own rules and could have effective access outside the selected folder's lock profile. | The lock checks descendants before changing the root. It refuses protected ACLs, incompatible explicit rules, and reparse points without rewriting child ACLs. |
| QA-11 | High | Scheduler retry backoff used the same key for lock and unlock. One failed operation could defer the opposite operation after a schedule change. Consecutive 24-hour windows also reported a lock time at their shared boundary. | The scheduler uses separate backoff keys for lock and unlock. Adjacent windows produce the actual end of the combined allowed period. |
| QA-12 | High | ConfigUI displayed editable extension choices in default ACL mode, recursively scanned on folder selection, and offered a polling interval the service ignored. Its auto-sizing status text could cross into the Settings panel. | Vault encryption has an explicit control. Scans run off the UI thread after the user requests them. The app removes the ignored polling control and keeps status text below the settings. |
| QA-13 | Critical | Uninstall stopped and deleted the Windows service without running standalone recovery. This could leave locked folders and remove the tools needed to restore them. The PowerShell uninstaller could also remove a caller-supplied install directory recursively. | Both supported install packages include Recovery. Uninstall stops and waits for the service, restores managed folders, and proceeds with removal only after successful recovery. Script removal is scoped to installed GameLocker files. |
| QA-14 | High | A temporary sharing failure disabled the service file logger for the process lifetime. A fixture held the first log write open exclusively, closed the handle, waited more than five seconds, and confirmed that the baseline still dropped the next message. | The logger retries after a short delay. The same fixture recorded the next message after releasing the handle. Rotation with zero retention kept no archive, and the default location uses Windows CommonApplicationData. |
| QA-15 | High | ConfigUI disabled editing without an administrator token, but the installed shortcut launched it without requesting elevation. Inno Setup's optional post-install launch also used the original user's credentials by default. [Inno Setup Run section](https://jrsoftware.org/inno-setup/documentation/topic_runsection.htm) | The ConfigUI executable requests elevation for an ordinary shortcut launch. Inno Setup gives the optional post-install launch its elevated token. |
| QA-16 | High | With both key sidecars missing, a fixture with pending vault files in one folder generated new keys and encrypted a save in a second folder. The newly generated keys cannot recover ciphertext written under the previous keys. An unreadable journal could conceal the same condition. | GameLocker checks persisted keys before encryption. When both sidecars are missing, pending vault files or any unreadable journal block key generation and further encryption. The fixture preserved the new save and left the key files absent. |

## Verification

- The Release solution built with zero warnings and zero errors. `UnlockTool`, `ForceDecrypt`, and `CheckConfig` also built in independent checks.
- The standard Release test run passed 91 tests and explicitly skipped the 10 ACL cases requiring an elevated Windows administrator token. New fixtures covered an interrupted ACL write, a drifted ACL, journal corruption and concurrent use, test-lock callback failure, child ACL compatibility, junction ancestry and scan exclusion, vault conflicts and integrity failures, restart restoration, legacy decryption, missing configuration sidecars, empty schedule persistence, and adjacent schedule windows. The missing-vault-key tests covered a fresh locker, a locker that previously loaded the keys, and an unreadable journal.
- A disposable legacy ACL fixture independently verified the corrected assertions. The deny blocked content rights, preserved ACL repair rights, and reached the nested directories. SYSTEM and Administrators had explicit allow entries.
- The managed ConfigUI startup check reached the WinForms message loop without creating production ProgramData. The Recovery executable returned exit code 0 for `--help`. The shortcut elevation change was checked in the ConfigUI executable's embedded manifest. The live UAC prompt and post-install launch still require an elevated desktop test.
- The PowerShell ZIP contained the Windows service, ConfigUI, Recovery, and its setup entry points. The Inno Setup offline compiler completed with exit code 0. An isolated PowerShell uninstall fixture verified service stop, wait, `restore-all`, then service removal. A recovery failure retained the installed payload, state, and service registration.
- A temporary log fixture verified that file logging resumed after an exclusive handle was released and rotated without keeping an archive when retention was zero.

## Recovery and test limits

- Legacy builds did not record file provenance or integrity. Use `GameLocker.Recovery restore-file <path>` for each file you can identify as GameLocker ciphertext. Verify the recovered plaintext and move the encrypted copy to a backup folder before retrying the folder restore.
- ACL preflight reads filesystem metadata and permissions and leaves file contents unchanged in ACL-only mode. The lock depends on compatible NTFS inheritance. Windows owners can retain implicit permission-management rights, and the lock is intended for scheduling ordinary access. To exercise the 10 skipped ACL cases, run `dotnet test tests/GameLocker.Tests/GameLocker.Tests.csproj --filter "Category=RequiresAdmin"` from an elevated Windows terminal. Actual service installation and uninstall and end-to-end desktop interaction also require an elevated Windows test session.
- Desktop automation could not start in this session, so GUI verification covered source, build, and startup. Windows notification delivery to the interactive user and the full visual workflow remain unverified.
- Interruption coverage verifies journal replay from persisted intermediate states. It does not include hardware power-loss tests.

## Installed Windows QA

On November 19, 2026, the EXE installer created and started the service on a Windows desktop. The test used a disposable NTFS directory with a synthetic game process, a 256-byte save, and an unselected asset. It used the installed service throughout and restored the test folder before clearing the test schedule.

| Scenario | Result on the baseline installation |
| --- | --- |
| Opening and cutoff within an allowed day | The folder stayed locked before the opening and unlocked 8.4 seconds after it. It locked 3.0 seconds after the closing boundary. |
| Already-running game at cutoff | The synthetic process stayed alive after GameLocker locked its folder. |
| Excluded day | The service locked the folder even though the current clock time was in the configured hours. |
| ACL-only mode | Locking left file bytes unchanged. Unlock and configuration removal restored the captured ACL. |
| Vault mode | Only `.sav` moved to ciphertext. The save and untouched asset matched their original SHA-256 digests after unlock, and the original ACL was restored. |

The follow-up vault regression exercises files held open with delete sharing. Encryption and decryption keep the open source intact until its reader releases it. The retry completes and restores the original save bytes.

In the upgraded installation, the opening and closing transitions were observed 224 ms and 208 ms after their scheduled times. The service requested a normal close in the interactive user session. The synthetic game wrote from its closing handler and exited before GameLocker changed the folder permissions. Opening the vault restored the original bytes and ACL 165 ms after its scheduled start. Separate process tests confirmed that an executable in a sibling directory and an executable reached through an outward junction are outside the managed folder. An identity check rejected an incorrect process creation timestamp.

The close request allows up to ten seconds for a game to save. A game with a save prompt, a disabled window, or no eligible window can remain running after the folder locks.

The installed configuration window rendered its schedule, folder list, vault controls, and save controls. Windows integrity isolation blocked automated input to the elevated window. The service checks used its normal saved-configuration and recovery paths, and the test schedule was cleared after the fixture was restored. The upgraded app remains installed.
