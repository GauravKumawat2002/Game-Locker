# Windows QA and remediation

The audit covers GameLocker’s scheduled lock and unlock, configuration, vault, recovery utility, and installer. Windows filesystem tests use disposable directories and synthetic file contents. Findings below describe the baseline behavior observed before remediation.

| ID | Severity | Baseline finding and evidence | Regression condition |
| --- | --- | --- | --- |
| QA-01 | Critical | `LockFolderAsync` saves `AclApplied=false`, changes the live ACL, then saves again. A process exit between the two writes leaves the snapshot on disk, but `HasOutstandingChanges` is false. Restart can replace the snapshot with the locked ACL, and recovery skips the record. | An interrupted apply remains recoverable. Lock retries reuse the original snapshot and restore verifies the result before discarding it. |
| QA-02 | High | `GetFolderState` detects live ACL drift but `LockFolderAsync` accepts any outstanding record as proof of lock. The scheduler repeatedly observes `Unknown` while the lock call does no work. The ACL verifier also permits direct access entries for arbitrary individual accounts. | Reapplying a lock corrects live drift and requires the expected protected ACL. |
| QA-03 | Critical | Vault encryption deletes originals before committing the batch manifest. The exception path also deletes a `.enc` file that existed before the attempt. Decryption opens the original with `FileMode.Create` and deletes it on failure. | Each ciphertext is verified and journaled before relinquishing its original. Conflicting or unreadable copies survive both operations. |
| QA-04 | Critical | Reconciliation treats any `.enc` extension as evidence of a GameLocker vault and invokes legacy decryption, even with no record or legacy lock. The legacy ACL path strips explicit denies and can reset an unrelated protected ACL. | Routine reconciliation leaves untracked ciphertext and unrelated ACL entries alone. Recovery may explicitly decrypt a legacy file. |
| QA-05 | High | The top-level test check rejects a reparse point only at the selected leaf. Recursive file enumerations follow child reparse points. The vault recovery path combines manifest entries with the folder without checking path containment. | A selected path with a reparse ancestor is rejected and scans and vault work stay within ordinary paths under the selected folder. |
| QA-06 | Critical | The ConfigUI test lock keeps its only ACL snapshot in a local variable. Closing the process before `finally` loses it. Removing a folder separately invokes the legacy ACL helper and scans every `.enc` file, then lets the saved service configuration relock it. Clearing can also leave outstanding folders behind. | Test lock uses the shared recoverable journal. Removing or clearing monitored folders hands restoration to the same reconciliation path and keeps unresolved records available. |
| QA-07 | High | `FolderStateStore.Save` ignores a failure to secure the state store. Unreadable or malformed records are returned as absent, so subsequent operations can replace the only recovery snapshot. Concurrent callers use the same uncoordinated temporary path. | Mutation stops on an unsecured or unreadable store, and one operation owns each folder journal at a time. |
| QA-08 | High | The service and Recovery initialize vault keys up front, so damaged or missing key files can stop ACL-only operations. Neither the primary installer build nor its payload contains `GameLocker.Recovery`. | An ACL-only operation is independent of vault keys and the standard installer includes an accessible recovery tool. |
| QA-09 | High | `LoadConfigResultAsync` reports a missing key/IV sidecar as `NotFound`, and ConfigUI consumes the overload that collapses unreadable configuration into first-run state. A save can overwrite the only encrypted config with new keys. | Missing sidecars produce a visible load error and saving cannot overwrite an unreadable configuration. |
